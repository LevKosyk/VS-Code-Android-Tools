# Security Policy

## Reporting a vulnerability

Please do not publish an exploitable vulnerability in a public issue. Use GitHub's private vulnerability reporting for this repository when available. If private reporting is unavailable, contact the maintainer through the publisher profile and include only enough information to establish a private channel.

Include the affected extension version, operating system, reproduction steps, impact, and a minimal proof of concept. Do not include real signing keys, access tokens, private source code, or personal device data.

## Scope

Security-sensitive areas include command execution and argument escaping, APK and archive processing, file operations, Webview message handling and content security policy, diagnostics exports, signing tools, and ADB operations against connected devices.

Only the latest Marketplace release is supported with security fixes.
